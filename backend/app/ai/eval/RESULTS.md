# AI 마감 추출 평가 결과 (2026-10-03 실호출)

README 와 PRD 에 적은 정확도 숫자의 원자료다. 공지마다 정답 초안, AI 없는 기준선, AI 결과, AI가 댄 근거 문장을 그대로 옮겼다.

## 조건

- 표본: 국민대 본부 게시판 4(학사)·6(특강)·7(장학)·9(공모·행사)·11(교외채용)에서 고정 공지를 빼고 최신 4건씩, 20건(2026-10-03 수집). 목록은 `gold_enrich.json`.
- 모델: 학교 AI 게이트웨이 `claude-opus-5`(분류·요약·마감), `claude-haiku-4-5`(포스터 글자 읽기).
- 명령: `python -m app.ai.eval.run_eval --llm gateway --yes`(글 경로 20건), `python -m app.ai.eval.run_poster_eval --yes`(포스터 6건).
- 기준선: `run_eval --llm baseline`. LLM 없이 제목 규칙(「(~10/15)」 같은 표기)만 쓴다.
- 비용: $0.416. 게이트웨이 사용액 값(2.6462 → 44.2228)을 센트로 보고 계산했다. 단위가 센트라는 것은 토큰 수 × 공식 가격과 맞아서 추정한 것이다. 토큰 수로는 글 경로 Opus 입력 36,410·출력 4,895, 포스터 Haiku 8,888·3,706, 포스터 뒤 Opus 9,623·1,340.

## 한계 (먼저 읽을 것)

- **정답은 사람이 확인하지 않았다.** 본문 공지 정답은 Claude 가 원문을 읽고 쓴 초안이고(`confirmed: false`), 포스터 정답은 Claude 가 이미지를 직접 열어 적었다.
- **표본 안 점수다.** 프롬프트를 이 20건을 읽은 뒤에 썼다. 새 공지로 다시 재야 일반화된 숫자가 된다.
- 20건은 작다. 「틀린 것이 몇 건이냐」로 읽고, 비율로 일반화하지 않는다.

## 포스터 경로 6건 (Haiku 가 이미지 글자를 읽고 Opus 가 마감을 뽑음)

- **틀린 1건(kmu-6-12331).** 수강 기간 끝(12.20)을 마감으로 잡았다. 그 날짜가 포스터에 실제로 있어서 근거 검사를 통과했다. 이 실행 뒤에 `deadline_label.py` 를 더해서, 날짜 바로 앞의 가장 가까운 항목 이름이 수강·교육·행사 같은 기간이면 마감으로 치지 않게 했다(`tests/test_deadline_label.py`). 이 수정은 실호출로 다시 재지 않았다.
- 이 실행에서 찾은 버그도 하나 고쳤다. 포스터의 「09.01 - 09.22」를 2009-01-09 로 읽어서, 근거가 포스터에만 있을 때 마감이 버려졌다(`dates.py`, `tests/test_dates.py`).

## 다시 돌리는 법

```bash
cd backend
python -m app.ai.eval.fetch_bodies                      # 본문 캐시 (커밋 안 함)
python -m app.ai.eval.run_eval --llm baseline           # 기준선, 비용 0
python -m app.ai.eval.run_eval --llm gateway --yes      # 글 경로, 약 $0.30
python -m app.ai.eval.run_poster_eval --yes             # 포스터 6건, 약 $0.11
```

키는 `backend/.env` 에 둔다(`backend/app/ai/README.md` 「환경변수」).
